# Native capture and input experiments

> Historical record: the logs, captures and corpora named below were deleted in the October 12, 2026 cleanup and are no longer in the repository or its history. New runtime output goes to `logs/`.

The standalone Python harness now has Windows capture and input backends, plus a small native receiver application for testing them without the game. Capture runs on the existing recognition thread and publishes immutable state in memory. The receiver is a separate process because this experiment measures delivery across a real application boundary; it does not make a separate recognition service part of the bot architecture.

## Run the owned-window test

From the repository root:

```powershell
$env:PYTHONPATH = (Resolve-Path 'tools/offline-bot').Path
$offlinePython = 'tools/model-runtimes/fastvlm-venv/Scripts/python.exe'
& $offlinePython -m bsgo_offline.native_test --output logs/offline-bot/native --focus-timeout 120
```

This opens an 800 by 500 test window, requests normal activation of that new window, and waits for verified foreground access and fully painted fixture pixels. If Windows refuses activation, click the test window and leave it focused until it closes. The test never brings an unrelated application forward or bypasses Windows foreground restrictions. It closes its receiver and joins its workers afterward. The current test output is native-report.json (`logs/offline-bot/native/native-report.json`); each run also keeps its uniquely named receiver directory.

The driver checks independent capture progress during a 0.5-second consumer delay, left/right/middle click receipts and client coordinates, PageUp/PageDown and letter key receipts, visual selection/throttle effects, cancellation of a held key, and rejection of a later window resize. It matches receiver messages to insertion records using injection tags. A request or a successful `SendInput` return is insufficient to pass this test.

## Implementations and evidence

[native_capture.py](../../tools/offline-bot/bsgo_offline/native_capture.py) copies the visible target client rectangle using GDI `BitBlt` and `GetDIBits`. It preserves RGB bytes independently of mutable Pillow images and establishes physical coordinates using a reversible thread DPI context. Window handle, process identity, foreground, visibility, minimized state, client size, origin, and sampled occlusion are checked. A guard failure invalidates that capture session; the existing worker publishes unhealthy unknown state. Moving or resizing requires a new inspected binding. Acquisition timestamps describe the capture operation, not a newly rendered game frame. `GetDIBits` runs only after restoring the previous selected bitmap, as required by [Microsoft's API contract](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-getdibits).

[native_input.py](../../tools/offline-bot/bsgo_offline/native_input.py) consumes the bounded recording queue and uses scan-code keyboard input and virtual-desktop absolute mouse coordinates. It checks the exact target and coordinate context before insertion, including the window covering a click point and unrelated held modifiers. It records insertion counts and partial failures separately from receiver receipt. Partial insertion cancels ordinary work and releases tracked injected holds. Releasing an already injected hold can be necessary after focus loss, but a cleanup PageDown press still requires the original target to pass its guards. No global input hooks or input `PostMessage` calls are used. Windows insertion and target validation are not atomic; [Microsoft documents `SendInput` insertion and integrity-level limits](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput).

[native_receiver.py](../../tools/offline-bot/bsgo_offline/native_receiver.py) records real key/button window messages, injection tags, client coordinates, repeats, and message-derived held state. It paints deterministic identity and state markers. The small pixel classifier reads those captured markers independently of the event/state files; those files are used only as separate acceptance evidence. Its event journal is bounded and flushed, with atomic latest-state files. It retains unobserved holds on shutdown rather than pretending that releases occurred.

An initial native run received all requested click coordinates exactly, changed the visible selection/throttle markers, advanced publication from sequence 1 to 9 during the consumer's 0.5-second delay, and released the held B key. Its partial result (`logs/offline-bot/native/c7890a54aab3/partial-result.json`), received events (`logs/offline-bot/native/c7890a54aab3/receiver-events.jsonl`), and captured final pixels (`logs/offline-bot/native/c7890a54aab3/native-after.png`) preserve that evidence. Receipt verification exposed mouse tag truncation: mouse messages returned only the low 32 bits of a 64-bit tag, while keyboard messages retained it. Tags now use `0x42000000 | sequence`, with an explicit 24-bit sequence limit and sequence zero reserved for emergency release.

The corrected native acceptance run passed on October 2, 2026. All 11 requests matched independently received key or mouse messages using the corrected tags; click coordinates met the one-pixel tolerance. The worker advanced from sequence 1 to 9 during the 0.5-second consumer delay. The fixture's visible selection and throttle states were observed from captured pixels, cancellation produced a received B-key release, and final receiver holds were empty. Resizing the receiver invalidated capture and published unknown state; a subsequent input request was rejected with zero inserted events. Recognition, input, and receiver shutdown all succeeded. See the accepted session report (`logs/offline-bot/native/f53a5e11402c/native-report.json`), received events (`logs/offline-bot/native/f53a5e11402c/receiver-events.jsonl`), and captured final pixels (`logs/offline-bot/native/f53a5e11402c/native-after.png`).

Earlier runs that could not obtain foreground access timed out without sending input. Foreground refusal remains a supported failure condition rather than an automatic retry that steals focus. There is no receiver or background test service left running.

At native acceptance, the Python suite passed 124 tests. These cover native ABI structure sizes, extended key scan codes, partial insertion, cleanup, target and geometry guards, DPI restoration, GDI cleanup, pixel rejection, and receipt matching. A saved real screenshot also produces identical OCR fields through the native RGB-frame adapter and the existing path-based adapter; explicit profile and image-size rejection remain intact.

The subsequent history fix makes request and native delivery histories rolling 64,000-entry memory windows; neither fills into a lifetime control stop. The driver now writes request, disposition, and insertion telemetry to a bounded asynchronous [TraceJournal](../../tools/offline-bot/bsgo_offline/trace.py) under each run's `trace/` directory. Full 64,000-event packages become verified ZIP archives before their raw segments are removed; partial packages remain raw. Reports expose retained/evicted counts, archive counts, journal enqueue gaps, disk errors, and writer shutdown. `native-input.jsonl` is explicitly a recent-history export with a `.stats.json` sidecar. The native receiver's own message journal remains a bounded test-fixture recorder. The earlier accepted native run predates this journaling integration; subsequent history checks use mocked native APIs and synthetic input, separately from that acceptance evidence.

## Limits that remain

This is a foreground visible-window GDI backend. Sampled occlusion checks do not detect every overlay, and it has not been accepted against BSGO's GPU-rendered surface, covered/minimized operation, or concurrent human desktop use. The native fixture measures application input delivery and pixel changes, not game movement, braking, resources, or rewards. Actual focus-loss and minimization rejection still have mocked coverage; resize rejection passed against the owned native window.

The dispatcher thread serializes this experiment's queued input and cleanup. It does not imply one mandatory worker per application module. The GDI capture call has no application-level cancellation deadline: a bounded recognition join reports failure if blocked, and the driver skips a blocking close when that join fails. General isolation or a different capture backend requires evidence of a practical problem, rather than an assumption that every capture operation needs a process.
